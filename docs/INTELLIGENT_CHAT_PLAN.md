# Intelligent BCM Chat - Plan

A second pass on the BCM chat experience. The current chat (BCM_PLAN.md, Parts B-E) does the mechanics: tool use, streaming, Kanban refresh. This plan upgrades it on two axes:

1. **UX**: a Claude Desktop-style conversational surface (markdown rendering, citations, visible reasoning, stop button, file uploads, suggested follow-ups).
2. **Intelligence**: lean on Anthropic-native features the current code is *not* using: extended thinking, server-side web search, Files API for PDFs/images with native citations, prompt caching, and a much stronger system prompt with worked examples.

This is a plan only. No code changes until decisions below are signed off.

## Goals

- Chat panel that visibly thinks, cites, and feels conversational.
- Agent that produces materially better BCMs than the current one - well-sourced, multi-step reasoned, iteratively refined.
- Native Anthropic API features over custom plumbing wherever they're a wash or better.

## Non-goals (this initiative)

- Computer use, voice I/O, multi-user collab on one chat.
- Migration to the Claude Agent SDK (we keep using the Messages API directly).
- New project types beyond Value Discovery.

## Decisions needed before code (kept here for reference)

These shape the architecture; please pick before we start.

### D1. OpenAI parity

Anthropic has four features OpenAI doesn't expose equivalently: extended thinking with budget control, **server-side web search** (no Tavily key needed), Files API with native PDF + citations, and prompt caching with structured cache breakpoints. Keeping full parity caps the experience at the lowest common denominator.

- **Option (a):** Drop OpenAI from the BCM chat. The provider abstraction shrinks; the existing OpenAI tests retire.
- **Option (b) - recommended:** Keep OpenAI as a "lite" mode that supports text + tool use only. New features (thinking, citations, file references, web search) are Anthropic-only. UI labels OpenAI mode as "Lite".
- **Option (c):** Keep full parity by using Tavily + pypdf for everything and dropping the new Anthropic features. Defeats the point.

### D2. Files: where PDFs and images live

When the user attaches a 50-page annual report or an org-chart screenshot, who stores it?

- **Option (a) - recommended:** Anthropic Files API. Upload once, reference by file id in subsequent messages. Claude reads PDFs natively with citations; images go through vision. We track `(project_id, anthropic_file_id, original_filename, kind)` in a new `bcm_files` table. No file bytes on our disk.
- **Option (b):** Local Docker volume + pypdf parse + send extracted text. Cheaper to revoke/audit; loses citations and image support.
- **Option (c):** Hybrid - Anthropic Files for the primary path, fall back to local for OpenAI mode.

### D3. Multiple chat threads per project

Today: one chat per project. Claude Desktop: many.

- **Option (a) - recommended:** One thread per project for v1 (matches existing schema). Add "branches" later if it actually feels needed.
- **Option (b):** Multi-thread now. Schema change: `bcm_chat_threads` table; messages reference a thread, not a project. UI gains a thread list / "New chat" button.

### D4. Memory across sessions

Anthropic now exposes a memory tool. The agent could remember "Acme is a SaaS with three product lines" without re-reading the website each session.

- **Option (a) - recommended for v1:** No persistent memory. Each turn rebuilds context from chat history + uploaded files. Add memory in a later phase if quality demands it.
- **Option (b):** Use the Anthropic memory tool from day one. Adds cross-session state and a small storage layer for the memory blob.

### D5. Extended thinking visibility

Anthropic's extended thinking returns separate `thinking` content blocks (or summarised, depending on settings).

- **Option (a) - recommended:** Show as a collapsible "Reasoning" block above each assistant message, collapsed by default, with a faint "Thought for Ns" header. Mirrors Claude Desktop.
- **Option (b):** Hide thinking from the UI; only the final response is visible.
- **Option (c):** Always-expanded thinking, ChatGPT o1-style.

### D6. Suggested follow-ups

After each turn, surface 2-3 next-step prompts the user can click ("Add an L1 for Risk", "Map opportunities for Customer Acquisition", "Refine to 7 L1s instead of 12").

- **Option (a) - recommended:** Yes, generated by the same model in a small structured tail call. ~$0.001 per turn.
- **Option (b):** Skip; not worth the complexity.

## Locked-in features (assuming the recommended options above)

These all use Anthropic Messages API; no Agent SDK.

1. **Server-side web search** via the `web_search_20250305` tool. Drops the Tavily dependency and the user-supplied Tavily key. Citations come back attached to the message.
2. **Extended thinking** with `thinking: {type: "enabled", budget_tokens: 8000}`. Streamed alongside text deltas as a separate "Reasoning" block.
3. **Prompt caching** with `cache_control` breakpoints on the (now much longer) system prompt and the tool definitions. Each turn after the first hits the cache.
4. **Files API** for user-uploaded PDFs / images, referenced by `file_id` in messages with native citations.
5. **Markdown rendering** in the chat (react-markdown + remark-gfm + a small list of allowed HTML tags). Code blocks with copy button; tables, lists, links.
6. **Citations** rendered as small numbered chips at the end of each paragraph; hover shows source URL + title; click opens in a new tab.
7. **Stop button** mid-stream via `AbortController`, wired through the existing `streamChat` signal.
8. **Drag-drop file upload** zone on the chat panel; same widget supports paste-image.
9. **Suggested follow-up prompts** as 2-3 chips below the latest assistant message.
10. **Stronger system prompt** with: an explicit reasoning rubric (research → identify business model → enumerate L1s → decompose), an example BCM (small, well-formed), and rules for when to ask the user for input vs proceed.

### Phase 4 - Iterative refinement

Goal: the agent proposes changes; the user accepts, rejects, or edits.

Backend:
- Two new tools instead of (or alongside) `set_capabilities`:
  - `propose_capability_changes(diff)` - emit a structured diff (additions, removals, renames, moves).
  - `apply_capability_changes(diff_id)` - apply a previously proposed diff after user confirmation.
- New table: `bcm_capability_diffs (id, project_id, message_id, diff_json, applied_at)`.
- Streaming: a new `diff_proposed` event; UI renders an inline diff card.

Frontend:
- Inline diff card with Accept / Reject / Tweak. Tweak opens a small editor on the diff before applying.

Tests:
- pytest: diff CRUD, apply persistence, conflict handling (capability deleted between propose and apply).
- Vitest: diff card renders, Accept fires the right API.
- pytest count target: ~125.

Success:
- "Add Risk Management as L1 with sub-capabilities for compliance and audit"; agent proposes a diff card; user clicks Accept; tree updates; chat shows "Applied".

## Risks / open questions to flag

- **Cost**: extended thinking + larger system prompt + web search calls roughly double token cost per turn vs current. Prompt caching offsets some of this. Worth measuring after Phase 1.
- **Latency**: extended thinking adds 5-15s before the first text token. The streaming UI hides most of this (the user sees reasoning streaming in), but the perception matters.
- **Anthropic API key permissions**: server-side web search requires the user's Anthropic key has the relevant feature enabled (no extra permission needed in practice; flag if it changes).
- **OpenAI degradation**: if D1 = b, expectations for OpenAI users need to be communicated honestly in the LLM Settings UI ("Lite mode - no web search, no thinking, no file citations").
- **Scope creep**: Phase 4 is its own week of work; willing to ship after Phase 3 if priorities shift.
